idp-server Client Instance 管理 API (1.0.0)

Download OpenAPI specification:Download

Client Instance（Attestation-Based Client Authentication の自己署名モードで使う、アプリのインスタンスごとの鍵）を管理する API です。

概要

Client Instance は、client_attestation_trust_source = registered_instance_key のクライアントで、 アプリのインストールごとに登録する鍵（Client Instance Key）です。アプリはこの鍵で Client Attestation JWT を自己署名し、 kid にインスタンスの id を入れます。詳しくは Attestation-Based Client Authentication を参照してください。

インスタンスはふつう、アプリ自身が登録エンドポイント（POST /{tenant-id}/v1/client-instances）で登録します。 この API は、運用側での検索・失効・削除と、アプリからの登録を使わない場合の登録に使います。

テナント直下のリソース

インスタンスはクライアントの下ではなくテナントの直下に置いています。運用で手元にあるのは利用者・鍵・証明書のシリアルで、 どのクライアントのものかは調べるまで分からないためです。id は UUID で、テナント内で 1 件に決まります。 client_id は登録時のボディと、検索条件で指定します。

失効と削除

失効（POST .../{id}/revoke） 削除（DELETE .../{id}）
意味 信頼をやめる 記録を消す
インスタンスの記録 残る（status: revoked、revoked_at、revocation_reason、証跡） 消える
その鍵での認証 拒否（401 invalid_client_attestation） 拒否
発行済みのトークン 削除 削除
同じ鍵の再登録 できない できる（別のインスタンスになる）

失効は元に戻せません。

権限

操作 権限
登録 idp:client-instance:create
検索・取得 idp:client-instance:read
失効 idp:client-instance:revoke
削除 idp:client-instance:delete

Client Instance の検索

テナント内のインスタンスを、クライアントをまたいで検索します。新しく登録したものから順に返します。

条件はすべて任意で、組み合わせられます。取りうる値が決まっている条件（status、revocation_reason、 UUID の user_id、日時の from / to）に合わない値は 400 を返します。空の一覧を返すと「該当なし」と読み違えるためです。

Client Instance の登録

運用側でインスタンスの鍵を登録します。アプリからの登録（client_instance_registration_policy）には縛られず、利用者にも束縛されません。

  • client_id は必須で、このテナントのクライアントであること
  • id を指定する場合は UUID で、どのインスタンスにも使われていないこと。省略するとサーバーが払い出します
  • instance_key は公開鍵の JWK であること（d などの秘密鍵の要素を含むと 400）
  • 同じテナントのいずれかのインスタンス（失効したものを含む）にすでに登録されている鍵は登録できません

Client Instance の削除

インスタンスの記録を消し、そのインスタンスに発行したトークンも削除します。 止めるだけなら失効（POST .../{id}/revoke）を使ってください。削除すると、同じ鍵をもう一度登録できるようになります（別のインスタンスとして扱われ、旧いトークンは引き継ぎません）。

Client Instance の失効

インスタンスの信頼をやめます。記録と証跡は残り（status: revoked、revoked_at、revocation_reason: operator）、 そのインスタンスに発行したトークンは削除します。リフレッシュトークンと、introspection で確かめるアクセストークンはその時点で止まります。 JWT のアクセストークンをリソースサーバーが手元で検証する場合は、有効期限まで通ります。

失効は元に戻せません。 すでに失効しているインスタンスを失効させようとすると 400 を返し、最初の revoked_at を保ちます。 端末をもう一度信頼するときは、アプリが新しい鍵を作って登録し直します（失効した鍵は再登録できません）。
